# code-review

提交前自查或审查他人变更时执行，输出按严重度分级的意见。

## 检查清单

**安全性（最高优先）**
- 密钥/凭据：不写入日志、错误信息、响应头；读 `.env`，绝不硬编码。
- 注入：上游响应透传与配置解析是否信任了外部输入。
- 路径：文件读写路径是否可被外部输入控制。

**正确性**
- 边界条件与错误路径：上游超时、额度耗尽、配置缺项。
- SSE 透传：事件顺序完整、不丢事件（prismd 一期核心）。
- 并发：quota/limits 计数是否有竞态（node:sqlite 单进程，注意异步交叉）。

**约定符合**
- TypeScript 禁用 `any`；目录结构与 `AGENTS.md` 约定一致。
- 提交信息符合 Conventional Commits。

## 输出格式

- 分级：`blocking`（必须修）/ `advisory`（建议修）/ `nit`（可选）。
- 每条：文件:行号 + 问题 + 建议改法。
- 不确定的标「需确认」，不编造。

## 范围纪律

只审变更本身；不做方案设计；不顺手重构无关代码。
